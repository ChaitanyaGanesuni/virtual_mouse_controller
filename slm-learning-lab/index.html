02

What it means for a model to "learn language"

real computation · n-gram model

This is a real (tiny) language model, trained in your browser by counting which word follows which. Drag training data and watch it get better: its predictions sharpen and its loss on unseen sentences falls. A Transformer learns the same thing, P(next token | previous tokens), with gradient descent in place of counting.

Learning curve · loss on 4 unseen sentences

Cross-entropy L = −(1/N)·Σ log P(actual next word). Lower is better. Perplexity = eL, roughly "how many words the model is torn between".

What the model learned (raw counts after "")

P(w | prev) = count(prev, w) / count(prev). These counts are this model's parameters. An SLM keeps millions of learned weights in their place, which lets it generalise to contexts it never saw.

03

A sentence's journey through a language model

illustrative tensors · real shapes

Type a sentence and press Play. Each stop shows the actual numbers and the tensor shape at that point. Embeddings use small made-up values (d = 8) because a real model learns them during training. At the last stop, add the predicted word and run again: that loop is autoregressive generation.

04

SLM vs LLM: same blueprint, different scale

exact parameter math · rough compute estimates

SLMs and LLMs are usually the same decoder-only Transformer. What differs is width (dmodel), depth (layers) and vocabulary. Move the controls and every number and drawing updates. Parameter counts use the exact GPT-2-style formula. Times are order-of-magnitude estimates for a typical laptop CPU.

Block width ∝ dmodel (log scale). One bar = one Transformer block (attention + feed-forward), on top of the embedding layer and under the LM head.

Where your model sits (log scale)

Try this: change the number of heads. The parameter count stays the same, because heads split dmodel into slices of size dmodel/H and add no new weights. Now double dmodel: the block parameters roughly quadruple, because they scale with d².
